Introduction

AzLang is a small, dynamically typed programming language designed to make the first steps in programming feel clear — while still teaching the ideas that professional languages use every day. It reads like Python, but every block has an explicit end, so structure is always visible.

Version 2.1 is a complete language: variables, collections, functions, closures, classes and inheritance, exceptions, pattern matching, async/await, modules, HTTP, JSON, and more than 130 built-in functions. The entire runtime is a single dependency-free JavaScript file that runs in Node.js and in any modern browser.

Designed for learners

One keyword per concept. No braces, no semicolons required, no boilerplate. You can explain a whole program out loud.

Designed to grow

Classes, inheritance, closures, lambdas, and pattern matching mean you never have to switch languages to learn more.

Designed to help

Errors are written in plain English, with the exact line, a hint, and often a “did you mean?” suggestion.

Designed to be free

No packages, no build step, no npm install. A text editor and a browser are enough — or one node command.

What's new in 2.1

  • Async/await and promises with async fun, await, Promise.all, Promise.all_settled, sleep, and retry.
  • HTTP and HTTPS with http_get, http_post, graphql, headers, JSON bodies, timeouts, and response size limits.
  • Modules with import, export, named imports, default exports, and a built-in net library.
  • Null-safe helpers such as get_path, coalesce, is_map, and ensure_list for incomplete API data.
  • More strings and collections: padding, truncation, URL/base64 encoding, grouping, sorting by key, chunking, and set operations.
  • Resource limits for execution time, request count, response size, and per-request time.
  • A browser-based Studio served by a tiny local Node.js process instead of a separate desktop executable.

What was new in 2.0

  • Classes and inheritance with class, extends, new, this, and super.
  • Exceptions with try, catch, and throw.
  • Pattern matching with match, case, default, and the _ wildcard.
  • Lambdas, default parameters, and destructuring loops.
  • Raw strings and multi-line strings.
  • JSON, sorting, higher-order helpers, and dozens of new built-ins.
  • A new Studio IDE with examples, error highlighting, autosave, and file support.
  • Full Unicode: Persian text, identifiers, and digits work naturally.
Try it first

Open the AzLang Studio, press Ctrl + Enter, and come back when you want the details. The Studio needs no installation.

Install & run

AzLang runs in the browser and from a terminal. On Windows, the installer puts the azlang command, the browser-based AzLang Studio, the docs, examples, and a Node.js runtime in one place. The language itself still has zero npm dependencies and no build step.

Windows installer (recommended)

Download the latest Setup file from GitHub Releases. It installs for the current user, so no administrator rights are required.

Download Setup.exe Portable ZIP All releases

  • Adds azlang to your user PATH; open a new terminal after setup.
  • Creates Start Menu and desktop shortcuts, associates .az files, and registers an uninstaller in Settings > Apps.
  • Includes its own Node.js runtime, so nothing else needs to be installed.

Run a file, a snippet, or the interactive shell:

azlang examples\hello.az

To uninstall, open Settings > Apps > AzLang > Uninstall or run uninstall.exe in the installation folder. Your autosaved Studio code is kept.

Browser Studio

Open AzLang Studio in any modern browser. The installed copy starts studio\studio-server.js with the bundled runtime; the server only serves local files and opens your default browser. Unlike a desktop executable, the editor is an ordinary web page, so networking and modules work with normal browser security rules. It needs no extra installation and works offline once the page is loaded.

From a source checkout, run node studio-server.js (or IDE.bat) and open the printed URL. The portable ZIP uses studio\AzLang Studio.vbs.

Manual installation

For other platforms or a source checkout, download or clone the repository and run the runtime with Node.js 18 or newer. No npm packages are used. 

node azlang.js examples/hello.az
node azlang.js -e "say 6 * 7"
node azlang.js --check examples/tour.az
node azlang.js

The portable ZIP contains the same files as the installed copy. Unzip it and run studio\AzLang Studio.vbs or bin\azlang.exe; it does not change PATH, file associations, or the registry.

Your first program

Create a file named hello.az with these lines:

# My first AzLang program
say "Hello, world!"

let name = "Ada"
say "Welcome, {name}!"

Run it with azlang hello.az (or node azlang.js hello.az from a checkout), or paste it into the Studio. The output is:

Hello, world!
Welcome, Ada!

Three ideas are already at work:

  • say prints a value and adds a new line.
  • let creates a variable. Names are case-sensitive.
  • Inside a string, {name} inserts the current value of name. This is called interpolation.
  • Everything after # is a comment and is ignored.

A slightly bigger example

let secret = 7
let guess = 7

if guess == secret
  say "You found it!"
elif guess > secret
  say "Too high."
else
  say "Too low."
end

Blocks begin with a keyword such as if and end with end. Indentation is not required by the language, but two spaces per level make the structure easy to read — and the Studio indents automatically.

Syntax & structure

A program is a sequence of statements. Statements normally end at a new line; a semicolon can separate two statements on one line. Blocks are opened by a keyword and closed by end. Curly braces are used only for maps, never for blocks. 

let a = 1; let b = 2
say a + b

if a < b
  say "a is smaller"
end

Identifiers

A name may start with a letter (any Unicode letter) or an underscore, followed by letters, digits (including Persian and Arabic-Indic digits), marks, or underscores. Names are case-sensitive: total, Total, and TOTAL are three different variables. 

let user_name = "Ada"
let maxScore = 100
let شهر = "Tehran"        # Unicode identifiers are allowed
let _private = true

say user_name, maxScore
say شهر

Comments

A comment starts with # and runs to the end of the line. There are no block comments; use one # line per comment line. Comments inside strings are just text. 

# This is a full-line comment
let price = 20   # ...and this is a trailing comment
say "The # symbol is plain text inside a string"

Blocks and indentation

Every block has an explicit closer. Indentation is free-form, but the Studio and all examples use two spaces. You cannot use end as a variable, and every opener needs exactly one end — the parser will tell you the line where one is missing. 

fun classify(n)
  if n < 0
    return "negative"
  elif n == 0
    return "zero"
  else
    return "positive"
  end
end

say classify(-5)
say classify(0)
say classify(5)

Programs can span files

Use import and export to split code into reusable modules. A module is still ordinary AzLang code; there is no package registry or build step. See Modules.

Variables & constants

Use let to create a variable and const to create a constant. A variable must be created before it is read or assigned; there is no implicit global variable creation. 

let count = 0
count = count + 1
count += 4
say count

const MAX_ITEMS = 100
say MAX_ITEMS

let name = "Ada"
say "Hello, {name}"

Assignment is a statement

Unlike expressions, an assignment does not produce a value. You cannot write let a = let b = 1 or if (x = 1). This avoids a whole family of beginner mistakes. = assigns; == compares.

Constants

const creates a binding that cannot be reassigned. Reading it is normal; assigning to it raises an error with a hint. Constants are still subject to the language's normal value semantics: a constant list can have items appended, because the binding is not changing, only the list's contents. 

const LIMIT = 10
say LIMIT * 2

# This is an error:
# LIMIT = 20

const colors = ["red"]
append(colors, "blue")   # allowed: the list itself is mutated
say colors

Scope

AzLang uses function scope, not block scope. An if, for, while, try, or match block does not create a new variable scope. A variable created inside a block remains visible after the block.

Functions and methods create a fresh local scope, with the defining environment as their parent. This is what makes closures work: an inner function can read and update variables from the function that created it. 

if true
  let message = "created inside if"
end
say message        # still visible: blocks do not create scopes

fun make_counter()
  let count = 0
  fun next()
    count += 1
    return count
  end
  return next
end

let tick = make_counter()
say tick(), tick(), tick()   # 1 2 3
Declare before use

Reading a variable that does not exist is a runtime error, not null. Assigning to an undeclared name is also an error. This catches typos early; the message even suggests the closest existing name.

Naming conventions

  • snake_case for variables and functions: user_name, total_price.
  • UPPER_SNAKE_CASE for constants: MAX_ITEMS.
  • PascalCase for classes: BankAccount, Shape.
  • Boolean names read naturally: is_ready, has_items.
  • Persian and other Unicode names are allowed, but keep a project consistent.

Numbers

There is one numeric type. Integers and decimals are both JavaScript-style double precision numbers, but display is polished: whole values print without a trailing .0, and floating-point noise is rounded for display (0.1 + 0.2 prints 0.3).

  • Persian (۱۲۳) and Arabic-Indic (١٢٣) digits are accepted anywhere a number literal is expected, including decimals.
  • Division by zero is an error, not Infinity. Modulo by zero is also an error.
  • Numbers can be converted with num(), int(), str(), and bool().
  • There are no hexadecimal, binary, or exponent literals. Use num("...") only for plain decimal strings.

Truthiness

Conditions do not require a boolean. These values count as false:

  • false
  • null
  • 0 (and any zero-valued number)
  • "" (an empty string)
  • [] (an empty list)
  • {} (an empty map)

Everything else is true, including non-empty strings, non-empty collections, functions, classes, and instances.

say bool(0), bool(1), bool(""), bool("x")
# false true false true

say bool([]), bool([0]), bool({}), bool({a: 1})
# false true false true

if [] 
  say "never printed"
end

Equality

== and != compare deeply for lists and maps, so [1, [2]] == [1, [2]] is true. Numbers are compared by value. Strings are compared exactly. Different types are never loosely equal: 1 == "1" is false. Instances compare by identity — two separately constructed objects are not equal even if their fields match.

Display and representation

say prints strings without quotes. Other values are shown in a readable representation: lists and maps use brackets and quotes, functions show as <fun name>, classes as <class Name>, and instances as ClassName {field: value}. Interpolation uses the same display rules, so "{name}" prints the raw string but "{list}" prints the bracketed form. 

say "text"          # text
say ["a", "b"]      # ["a", "b"]
say {x: 1}          # {x: 1}

class Point
  fun init(x, y)
    this.x = x
    this.y = y
  end
end

say new Point(2, 3)   # Point {x: 2, y: 3}

Comparison

== and != work with every type. Ordering comparisons (<, <=, >, >=) require two numbers or two strings; comparing a number with a string is an error. 

say 3 > 2, 3 >= 3, 2 != 5       # true true true
say "apple" < "banana"            # true
say [1, 2] == [1, 2]              # true
say {a: 1} == {a: 1}              # true
say 1 == "1"                      # false

Logic

and, or, and not always return booleans, not the original operands. They short-circuit: the right side is not evaluated when the result is already known. 

say true and false        # false
say true or false         # true
say not true              # false

let age = 20
let has_ticket = true
if age >= 18 and has_ticket
  say "Welcome"
end

# Short-circuit protects the division:
if age != 0 and 100 / age > 2
  say "ok"
end

Membership

in checks list items (deep equality), map keys, and substrings. Use not in for the negated form. The right-hand side must be a list, map, or string. 

say 2 in [1, 2, 3]             # true
say "da" in "Ada"              # true
say "name" in {name: "Ada"}    # true
say 5 not in [1, 2]            # true

What is not here

  • No ++ or --; write x += 1.
  • No bitwise operators (&, |, ^, <<, >>).
  • No ternary ?:; use if/else or a small function.
  • No assignment inside expressions, and no chained assignment (a = b = 1).

Strings

Strings use single or double quotes. They support interpolation, escapes, raw literals, and triple-quoted multi-line form. All strings are Unicode: indexing and len work on characters (code points), not on bytes. 

let first = 'single quotes'
let second = "double quotes"
say first, second

let name = "Ada"
say "Hello, " + name

Interpolation

Any expression inside { } is evaluated and inserted. This includes variables, arithmetic, function calls, property access, and nested strings. 

let name = "Ada"
let scores = [90, 95, 100]

say "Hello, {name}!"
say "Total: {sum(scores)}"
say "Average: {sum(scores) / len(scores)}"
say "Upper: {upper(name)}"
say "Quoted: {upper('abc')}"

# A literal brace is written with a backslash:
say "Use \{curly braces\} for interpolation"

Raw strings

Prefix a string with r to disable escapes and interpolation. Raw strings are perfect for JSON, file paths, and any text full of braces or backslashes. A raw string ends at the first matching quote; it cannot contain that quote. 

let json_text = r'{"name": "Ada", "tags": [1, 2]}'
let user = json_decode(json_text)
say user.name

let path = r"C:\Users\Ada\notes.az"
say path

say r"no {interpolation} and no \n here"
JSON and braces

In a normal string, { begins interpolation. Always use a raw string for JSON text: json_decode(r'{"a": 1}').

Multi-line strings

Three quotes open a multi-line string. New lines are preserved, and normal interpolation still works. The indentation you type is part of the string. 

let name = "Ada"
let letter = """
Dear {name},

Welcome to AzLang.
"""

say letter
say len(letter)

Working with strings

let s = "  Hello, AzLang  "

say len(s)                 # 17
say trim(s)                # "Hello, AzLang"
say upper(trim(s))         # "HELLO, AZLANG"
say lower(trim(s))         # "hello, azlang"
say starts(trim(s), "He")  # true
say ends(trim(s), "ng")    # true
say find(s, "Az")          # 9
say replace(s, "AzLang", "world")
say split("a,b,c", ",")    # ["a", "b", "c"]
say join(["a", "b"], "-")  # "a-b"
say chars("Az")            # ["A", "z"]

let word = "AzLang"
say word[0], word[-1]      # A g
say slice(word, 2, 5)      # Lan
say word * 2               # AzLangAzLang

Strings are immutable: functions like upper, replace, and slice return new strings. Indexing uses zero-based positions, and negative indexes count from the end. There is no slice syntax like [1:3]; use slice(text, start, end).

Numbers and text

str(x) converts a value to its display string. num(text) parses a decimal string (Persian digits included) and errors on anything that is not a number. int(text) truncates toward zero.

Conditions

if runs a block when a condition is truthy. Add any number of elif branches and an optional else. The whole chain closes with one end. 

let score = 87

if score >= 90
  say "Excellent"
elif score >= 80
  say "Very good"
elif score >= 70
  say "Good"
else
  say "Keep practicing"
end

Conditions are ordinary expressions. Parentheses are allowed but never required. The condition is evaluated only until the result is known, thanks to short-circuit logic. 

let age = 20
let has_ticket = true

if age >= 18
  if has_ticket
    say "Enter"
  else
    say "Buy a ticket first"
  end
else
  say "Adults only"
end

Things to remember

  • Use elif, not else if. The parser gives a specific hint if you write else if.
  • Assignment is a statement, so if x = 1 is not valid. Use == to compare.
  • An empty block is not allowed; put at least one statement (or a comment line) inside.
  • Only the first matching branch runs. There is no fall-through.

There is no ?: operator

AzLang deliberately leaves out the ternary conditional. For a quick choice, use an if block or a tiny function. The function form is often clearer anyway: 

fun larger(a, b)
  if a >= b
    return a
  end
  return b
end

say larger(10, 4)

# Or, for a label:
fun label(ok)
  if ok
    return "yes"
  end
  return "no"
end
say label(3 > 2)

Loops

AzLang has three loop forms: while, for, and repeat.

while

The condition is checked before every iteration. Use it when the number of repetitions is unknown.

let count = 3

while count > 0
  say count
  count -= 1
end

say "Liftoff!"

for ... in

for walks over a list, a string, a map, or any list produced by helpers such as range. The loop variable is defined in the current scope. 

# A list
for fruit in ["apple", "banana", "cherry"]
  say fruit
end

# A string, character by character (Unicode aware)
for letter in "Az"
  say letter
end

# A range: start is inclusive, stop is exclusive
for n in range(1, 4)
  say n
end

# A map yields its keys
for key in {a: 1, b: 2}
  say key
end

Looping with two values

Name two variables to destructure pairs. This works with maps, enumerate, and zip. A map produces [key, value] pairs directly. 

let scores = {Ada: 95, Grace: 98}

for name, score in scores
  say "{name}: {score}"
end

for index, value in enumerate(["a", "b", "c"])
  say "{index} = {value}"
end

for left, right in zip([1, 2, 3], ["one", "two", "three"])
  say left, right
end

repeat

repeat runs a block a fixed number of times. The count must be a non-negative whole number. It is ideal for simple drills and animations. 

repeat 3
  say "Hello!"
end

break and continue

break leaves the innermost loop immediately. continue skips the rest of the current iteration and jumps to the next one. Both are only valid inside a loop. 

let numbers = [4, 9, 15, 22, 8]

for n in numbers
  if n % 2 == 0
    continue        # skip even numbers
  end
  if n > 20
    break           # stop at the first number above 20
  end
  say n
end

FizzBuzz

The classic exercise, expressed with elif:

for n in range(1, 16)
  if n % 15 == 0
    say "FizzBuzz"
  elif n % 3 == 0
    say "Fizz"
  elif n % 5 == 0
    say "Buzz"
  else
    say n
  end
end
Infinite loops are caught

A program may execute at most five million interpreter steps by default. A runaway while true stops with a friendly message instead of freezing the browser. The Studio also guards long output.

Loop variables persist

Because blocks share the surrounding scope, the loop variable still exists after the loop and holds its last value. If you need a fresh variable, give it a different name or wrap the loop in a function.

Functions

Functions are declared with fun, a name, a parameter list, a body, and end. Call them with parentheses. A function without an explicit return returns null. 

fun greet(name)
  return "Hello, " + name + "!"
end

say greet("Ada")

fun show_twice(text)
  say text
  say text
  # no return: result is null
end

let result = show_twice("hi")
say result        # null

Parameters and defaults

Parameters may have default values. Defaults are evaluated at call time, in order, so a later default can use an earlier parameter. Required parameters must come before parameters with defaults. 

fun power(base, exponent = 2)
  return base ** exponent
end

say power(5)        # 25
say power(2, 10)    # 1024

fun repeat_text(text, times = 1, separator = " ")
  let parts = []
  repeat times
    append(parts, text)
  end
  return join(parts, separator)
end

say repeat_text("ha")
say repeat_text("ha", 3, "-")
say repeat_text("ha", 2, "")

Passing too many arguments, or omitting one without a default, raises a runtime error that names the function and the missing parameter.

Return values

return ends the function immediately. It can appear anywhere inside the body, including inside loops and conditionals. Returning no value is the same as returning null. 

fun first_even(numbers)
  for n in numbers
    if n % 2 == 0
      return n
    end
  end
  return null
end

say first_even([3, 7, 8, 9])   # 8
say first_even([1, 3, 5])     # null

Recursion

A function can call itself. Recursion is limited to 256 nested calls; deeper recursion raises an error instead of overflowing the stack. Always include a base case. 

fun factorial(n)
  if n <= 1
    return 1
  end
  return n * factorial(n - 1)
end

say factorial(6)    # 720

fun fib(n)
  if n < 2
    return n
  end
  return fib(n - 1) + fib(n - 2)
end

say fib(10)         # 55

First-class functions

Functions are values. You can store them in variables, pass them to other functions, return them, and keep them in lists and maps. A function keeps a reference to the environment where it was created; this is a closure. 

fun make_multiplier(factor)
  fun multiply(value)
    return value * factor
  end
  return multiply
end

let double = make_multiplier(2)
let triple = make_multiplier(3)

say double(10)      # 20
say triple(10)      # 30

fun apply_twice(fn, value)
  return fn(fn(value))
end

say apply_twice(double, 3)   # 12

Arrow lambdas

For short operations, write parameter => expression or (a, b) => expression. A lambda is a single expression whose value is returned automatically; it has no block body. Lambdas capture their environment just like named functions. 

let square = x => x * x
let add = (a, b) => a + b

say square(9)       # 81
say add(2, 3)       # 5

let numbers = [1, 2, 3, 4, 5, 6]
say map(numbers, n => n * 10)
say filter(numbers, n => n % 2 == 0)
say reduce(numbers, (total, n) => total + n, 0)

Functions are small programs

Prefer many small, focused functions over one long one. A function that fits on a screen is easy to name, test, and reuse. Build larger behavior by composing helpers such as map, filter, and reduce.

No overloading, no varargs

There is exactly one signature per function name; redefining a name replaces the old function. Extra arguments are not collected automatically. Keyword arguments are not supported — pass values by position, or use a map for named options.

Async & promises

Network requests and timers take time. Instead of blocking the whole program, AzLang lets you mark work as asynchronous: the function returns a promise, and await pauses only the current function until the result is ready.

Async functions

Put async before fun. An async function always returns a promise. Calling it starts the work immediately; use await to read the value it produces. 

async fun load_user(id)
  await sleep(100)                  # pretend the server is slow
  return {id: id, name: "Ada"}
end

async fun main()
  say "loading..."
  let user = await load_user(7)
  say "Hello, {user.name}!"
end

await main()

await works on a promise, on a native JavaScript thenable, or on an ordinary value (in which case it simply returns the value). It can be used inside an async function, an async lambda, and at the top level of a program run with runAsync — which includes the CLI and the Studio.

Awaiting several tasks

Starting an async function does not wait for it. You can start several tasks, keep their promises, and wait for all of them together: 

async fun fetch_score(name)
  await sleep(50)
  return {name: name, score: len(name) * 10}
end

let jobs = [fetch_score("Ada"), fetch_score("Grace"), fetch_score("Linus")]
let scores = await Promise.all(jobs)

for item in scores
  say "{item.name}: {item.score}"
end

Async lambdas and methods

Arrow lambdas can be async too. Write async x => await work(x) or async (a, b) => .... Class methods use the same async fun spelling inside the class body. 

let load = async url => await http_get(url)
let fetch_text = async url => response_text(await http_get(url))

let response = await load("https://example.com/api")
let body = await fetch_text("https://example.com/api")

class Fetcher
  fun init(base)
    this.base = base
  end

  async fun get(path)
    return await http_get(this.base + path)
  end
end
Lambdas are expressions

An arrow lambda has a single expression body. For several statements, use a named async fun instead. Async lambdas are still useful for callbacks that must perform one awaited operation.

Errors in async code

A rejected promise behaves like an exception at the point where you await it, so ordinary try / catch works: 

async fun load(url)
  try
    let response = await http_get(url, {timeout_ms: 5000})
    raise_for_status(response)
    return response_json(response)
  catch err
    say "Request failed: {err.message}"
    return null
  end
end

let data = await load("https://example.com/api")
if is_null(data)
  say "Using cached data instead."
end
Synchronous embedding cannot wait

az.run() and session.execute() are synchronous and cannot wait for a promise. Calling an async function, sleep, or an HTTP helper from them raises an error that tells you to use az.runAsync() / session.executeAsync(). The CLI and Studio already use the async path.

A promise that is never awaited may still fail. AzLang marks such rejections as handled so Node does not terminate the process, but the error is not silently repaired: if you later await the same promise, the failure is thrown. Await or catch work you start.

Lists

A list is an ordered, mutable sequence written with square brackets. Lists can hold any mix of values and can be nested. 

let fruits = ["apple", "banana", "cherry"]
let mixed = [1, "two", true, null, [3, 4]]
let empty = []

say fruits
say mixed
say len(fruits)      # 3
say fruits[0]        # apple
say fruits[-1]       # cherry

Indexes start at zero. Negative indexes count from the end: -1 is the last item, -2 the one before it. An out-of-range index is a runtime error, never a silent null.

Reading and writing

let scores = [10, 20, 30]

scores[1] = 25
say scores              # [10, 25, 30]

scores[0] += 5
say scores              # [15, 25, 30]

let matrix = [[1, 2], [3, 4]]
say matrix[1][0]        # 3
matrix[1][0] = 9
say matrix              # [[1, 2], [9, 4]]

Growing and shrinking

append, prepend, insert, remove, discard, pop, sort, and reverse mutate the list in place. sorted, reversed, and slice return new lists. 

let items = [3, 1, 2]

append(items, 4)         # add to the end
prepend(items, 0)        # add to the front
insert(items, 2, 99)     # insert before index 2
say items                # [0, 3, 99, 1, 2, 4]

let removed = pop(items)     # removes and returns the last item
say removed, items           # 4 [0, 3, 99, 1, 2]

sort(items)
say items                    # [0, 1, 2, 3, 99]

let descending = sorted(items, "desc")
say descending               # [99, 3, 2, 1, 0]
say items                    # unchanged

Copies and aliases

Assigning a list to another variable copies the reference, not the items. Both names then point to the same list. Use list(items) or slice(items) to make a shallow copy. 

let a = [1, 2]
let b = a
append(b, 3)
say a               # [1, 2, 3] — the same list

let c = list(a)
append(c, 4)
say a               # [1, 2, 3]
say c               # [1, 2, 3, 4]

No list comprehensions

AzLang keeps the syntax small. The map, filter, and reduce helpers cover the same ground and read well with arrow lambdas.

Maps

A map stores values under keys. Keys are always strings internally: bare names, quoted strings, and numbers in a literal are converted to strings. Maps keep insertion order, which makes them predictable to print and loop over. 

let person = {
  name: "Ada",
  age: 36,
  skills: ["math", "logic"]
}

say person.name              # Ada
say person["age"]            # 36
say person.skills[0]         # math
say len(person)              # 3

Dot access is shorthand for string keys. Both person.name and person["name"] read the same entry. Reading a missing key is an error; use get(map, key, default) when a key may be absent. 

let scores = {Ada: 95}

scores["Grace"] = 98         # add a new key
scores.Ada = 96              # update an existing key
say scores                   # {Ada: 96, Grace: 98}

say get(scores, "Linus", 0)  # 0
say has(scores, "Ada")       # true
say "Grace" in scores        # true

remove(scores, "Ada")
say scores                   # {Grace: 98}
Keys are strings

let ages = {1: "one"} stores the key "1". Read it with ages["1"] or ages[1]; both work, because bracket access converts the key to a string. Choose consistent key styles to avoid surprises.

Iterating over maps

With one loop variable you get keys. With two, you get key/value pairs. The helpers keys, values, and items produce lists when you need to store or transform them. 

let ages = {Ada: 36, Grace: 40, Linus: 25}

for name in ages
  say name
end

for name, age in ages
  say "{name} is {age}"
end

say keys(ages)      # ["Ada", "Grace", "Linus"]
say values(ages)    # [36, 40, 25]
say items(ages)     # [["Ada", 36], ["Grace", 40], ["Linus", 25]]

Merging and updating

let defaults = {theme: "dark", font_size: 14}
let custom = {font_size: 18, lang: "en"}

let settings = defaults + custom
say settings
# {theme: "dark", font_size: 18, lang: "en"}

let target = {a: 1}
update(target, {b: 2, c: 3})
say target        # {a: 1, b: 2, c: 3}

set(target, "d", 4)
say target.d      # 4

A small word counter

Maps are the natural choice for counting. Combine them with split, has, and items: 

let text = "the cat and the dog and the bird"
let counts = {}

for word in split(text)
  if has(counts, word)
    counts[word] += 1
  else
    counts[word] = 1
  end
end

for word, n in counts
  say "{word}: {n}"
end

Maps are also the bridge to JSON: json_encode turns any map (including nested lists and maps) into text, and json_decode turns text back into maps and lists. See JSON.

Modules

A module is an AzLang file that exports names for other files to use. Modules keep programs organized without a package manager, a build step, or a registry: the import path points directly at the file (or URL).

Exporting

Declarations are private unless they are exported. Put export before fun, async fun, class, let, or const, or export existing names with a list. 

export const version = "1.0"

export fun add(a, b)
  return a + b
end

export async fun fetch_data(url)
  return await http_get(url)
end

fun private_helper(x)
  return x * 2
end

export { private_helper as double }

export default {
  name: "mathlib",
  version: version
}

A default export is reached through a namespace import: import tools from "./tools.az" then tools.default. Named imports use the exported keys, so export { add as plus } is imported as import { plus } from ….

Loading rules

  • Each module runs once per interpreter. Later imports reuse the same exports map, so module-level state is shared.
  • Named imports are checked: importing a name the module does not export is an error that lists the available exports.
  • A module can import other modules. Its own imports resolve relative to its file, not the main program.
  • export is only valid at the top level of an imported module. A script you run directly cannot export.
  • Errors raised while a module loads keep their own line numbers and gain a hint naming the module.
  • Cycles are allowed but risky: an import that is still running sees only the exports defined before the cycle. Prefer a one-way dependency graph.

Remote modules

A module URL can be imported directly. This is useful for sharing small libraries without installing them: 

import { greet } from "https://example.com/az/greet.az"

say greet("Ada")

In a browser, the server must allow cross-origin reads (CORS). The Studio is served over http://127.0.0.1 rather than opened as a file:// page, so relative and remote module imports work normally.

Modules are just files

There is no package registry and no dependency installation. Copy a .az file into your project, import it by path, and commit it with the rest of your code. This keeps projects readable and offline-friendly.

Classes

Classes bundle data and behavior. A class body contains methods declared with fun. Create an instance with new. Inside methods, this refers to the instance. 

class Point
  fun init(x, y)
    this.x = x
    this.y = y
  end

  fun length_squared()
    return this.x ** 2 + this.y ** 2
  end

  fun describe()
    return "({this.x}, {this.y})"
  end
end

let p = new Point(3, 4)
say p.x, p.y             # 3 4
say p.length_squared()   # 25
say p.describe()         # (3, 4)

p.x = 6
say p.describe()         # (6, 4)
say type(p)              # instance
say type(Point)          # class

How construction works

  • new Point(3, 4) creates a fresh instance, then calls init with the arguments.
  • init is optional. A class without it can only be created with no arguments.
  • Fields are not declared separately; assign this.name = value to create one.
  • Calling Point(3, 4) without new is an error with a hint.
  • Each instance has its own fields; methods are shared through the class.

Methods and state

Methods can read and change fields. A method may call other methods through this. Returning this enables simple chaining. 

class Counter
  fun init(start = 0)
    this.value = start
  end

  fun bump(amount = 1)
    this.value += amount
    return this
  end

  fun get()
    return this.value
  end
end

let counter = new Counter()
counter.bump().bump(5)
say counter.get()      # 6

Inheritance

A class can extend one parent class with extends. It inherits every method. Redefine a method to override it. Use super(args) to call the parent constructor, and super.method(args) to call a parent method. 

class Animal
  fun init(name)
    this.name = name
  end

  fun speak()
    return "{this.name} makes a sound"
  end

  fun introduce()
    return "I am {this.name}"
  end
end

class Dog extends Animal
  fun init(name)
    super(name)
  end

  fun speak()
    return super.speak() + ": woof!"
  end
end

class Puppy extends Dog
  fun speak()
    return super.speak() + " (small)"
  end
end

let animals = [new Animal("Cat"), new Dog("Rex"), new Puppy("Pip")]

for animal in animals
  say animal.speak()
  say animal.introduce()
end

Dog inherits introduce from Animal and overrides speak. Puppy extends Dog, so super.speak() reaches Dog's version, which itself calls Animal's version. This is ordinary dynamic dispatch: the method chosen depends on the instance.

Instances in practice

class Account
  fun init(owner, balance = 0)
    this.owner = owner
    this.balance = balance
  end

  fun deposit(amount)
    if amount <= 0
      throw {message: "Deposit must be positive", code: "bad_amount"}
    end
    this.balance += amount
    return this.balance
  end

  fun withdraw(amount)
    if amount > this.balance
      throw {message: "Not enough funds", code: "no_funds"}
    end
    this.balance -= amount
    return this.balance
  end
end

let account = new Account("Ada", 100)
account.deposit(50)
say account.balance       # 150

try
  account.withdraw(500)
catch problem
  say problem.message     # Not enough funds
  say problem.code        # no_funds
end

What classes do not have

  • No static methods or class-level state.
  • No private or protected members; all fields are public.
  • No interfaces, mixins, or abstract classes.
  • No constructor overloading; one init per class.
  • No toString override: say instance uses the built-in representation.
Composition over inheritance

Use inheritance when the “is a” relationship is real (a Dog is an Animal). Otherwise, give a class a field that holds another object. It is usually easier to change later.

Exceptions

Errors are values in AzLang. Use try to protect a block, catch to handle a failure, and throw to raise your own. This works for both errors you create and runtime errors such as dividing by zero. 

try
  say 10 / 0
catch problem
  say "Something failed:"
  say problem.message     # Cannot divide by zero
  say problem.line        # the source line
end

The catch variable is optional; the default name is err. Blocks close with one end after the catch body. 

try
  throw "custom failure"
catch
  say err
end

What a caught error contains

A runtime error arrives as a map with four keys. Errors thrown with throw keep whatever value you supplied, so you can throw a string, a number, a list, or a map of your own.

FieldMeaning
messagehuman-readable description

try
  let values = [1, 2]
  say values[10]
catch e
  say e.kind        # runtime
  say e.line        # 3
  say e.message     # Index 10 is out of range (length is 2)
  if e.hint != null
    say e.hint
  end

Throwing your own errors

The most useful pattern is a map with a message and an optional machine-readable code. Add any extra fields you need, such as the invalid value. 

fun parse_positive(text)
  let value = num(text)
  if value <= 0
    throw {
      message: "Expected a positive number",
      code: "not_positive",
      value: value
    }
  end
  return value
end

try
  say parse_positive("0")
catch e
  say e.message          # Expected a positive number
  say e.code             # not_positive
  say e.value            # 0
end

Re-throwing

A catch block can inspect an error and throw it again (or wrap it in a new one) when it cannot handle the problem: 

try
  try
    throw {message: "disk full", code: 507}
  catch e
    say "Logging: {e.message}"
    throw e
  end
catch outer
  say "Top level handled: {outer.code}"
end

assert and fail

assert(condition, message) throws when the condition is false. fail(message) always throws. Both are useful while learning and while writing tests; they create ordinary catchable errors. 

fun average(numbers)
  assert(len(numbers) > 0, "average needs at least one number")
  return sum(numbers) / len(numbers)
end

say average([2, 4, 6])

try
  average([])
catch e
  say e.message     # average needs at least one number
end

# fail("unreachable")
No finally block

There is no finally. Put cleanup statements after the try/catch block; they run whether or not an error was handled, as long as control reaches them.

Catch what you can handle

Avoid wrapping entire programs in a catch that only prints “something went wrong”. Catch close to the operation that can fail, handle the specific case, and let unexpected errors surface with their line number and hint.

Pattern matching

match compares one value against several possibilities. Each case can list one or more values; the first match runs and the rest are skipped. An optional default handles everything else. The block closes with end. 

let status = 404

match status
  case 200, 201, 204
    say "success"
  case 301, 302, 307
    say "redirect"
  case 400, 401, 403, 404
    say "client error"
  case 500, 502, 503
    say "server error"
  default
    say "unknown status"
end

Values are compared with the same deep equality used by ==, so lists and maps can be matched too. The wildcard _ matches anything; it is the same idea as default but can sit among the cases. 

fun describe(value)
  match value
    case 0
      return "zero"
    case 1, 2, 3
      return "a small number"
    case [1, 2]
      return "the list [1, 2]"
    case {kind: "user"}
      return "a user map"
    case _
      return "something else"
  end

Dispatch on type

Matching on type(value) is a clean alternative to long if type(x) == ... chains: 

fun render(value)
  match type(value)
    case "number"
      return "number: {value}"
    case "string"
      return "text of length {len(value)}"
    case "list"
      return "list of {len(value)} items"
    case "map"
      return "map with keys {keys(value)}"
    default
      return "another kind of value"
  end
end

say render("hello")
say render([1, 2, 3])
say render({a: 1})

How match behaves

  • The subject expression is evaluated once.
  • Case expressions are evaluated in order, from top to bottom, until one matches.
  • A case may contain several values separated by commas.
  • Only the first matching case runs. There is no fall-through.
  • default runs only if nothing matched. case _ is a wildcard that can appear anywhere.
  • match is a statement. To produce a value, return from a function inside each case.
No binding patterns

Cases compare against values; they do not destructure or bind variables. Use ordinary if checks for conditions and for destructuring for pairs.

Null-safe data

API responses are rarely complete. A field may be absent, null, or the wrong type, and a direct chain such as response.user.profile.name stops with an error at the first missing link. AzLang provides helpers that read through missing values and return a default instead.

Reading a path

get_path(value, path, default?) walks maps and lists. A path is a string using dots and brackets, or a list of keys. If any step is missing, the default is returned (null when no default is given). 

let payload = {
  user: {name: "Ada", email: null},
  posts: [{title: "Hello"}, {body: "No title here"}],
  meta: {}
}

say get_path(payload, "user.name")                     # Ada
say get_path(payload, "user.email", "unknown")         # null is a value, so this prints null
say get_path(payload, "user.phone", "unknown")         # unknown
say get_path(payload, "posts[1].title", "(untitled)")
say get_path(payload, ["posts", 0, "title"])

say has_path(payload, "user.name")                     # true
say has_path(payload, "user.phone")                    # false
Present but null

get_path returns a key that exists even when its value is null. Use coalesce or fallback when null should also fall back to a default.

A tolerant API reader

async fun profiles(url)
  let response = await http_get(url)
  raise_for_status(response)
  let data = response_json(response)

  let items = ensure_list(get_path(data, "items"))
  let result = []

  for item in items
    let profile = ensure_map(item)
    append(result, {
      name: coalesce(get_path(profile, "name"), "anonymous"),
      city: get_path(profile, "address.city", "unknown"),
      tags: ensure_list(get_path(profile, "tags")),
      active: get_path(profile, "active", false)
    })
  end

  return result
end

  say "{person.name} ({person.city})"
  say "  tags: {tag_text}"

The same idea works for ordinary maps, configuration files, and JSON read from disk. Reading a missing key directly with map[key] is still an error — that is deliberate, because it usually indicates a bug. Use get_path when the data is genuinely optional.

Small defaults beat deep nesting

Prefer a shallow get_path with a sensible default over a long chain of if is_map(...) checks. If every field needs a different fallback, normalize the response once at the edge of your program, then use plain maps internally.

AzLang reports two kinds of problems. Syntax errors are found before the program starts; the program does not run at all. Runtime errors happen while executing and can be caught with try / catch.

  2. Print the inputs. say type(x), x before the failing line answers most questions.
  3. Use type(). A string "5" and the number 5 are different values.
  4. Check boundaries. Indexes start at 0; range(a, b) stops before b; slice end is exclusive.
  5. Check declarations. Assigning to an undeclared name is an error, so a missing let can look like a scope bug.
  6. Use --check. It catches syntax problems without executing side effects.
  7. Use assert. Put assumptions in code while you learn; a failed assertion names the exact line.

Errors are values

Inside catch, a runtime error is a map with message, line, kind, and hint. HTTP and GraphQL errors add fields such as status, url, body, errors, data, and response. You can inspect it, log it, wrap it, or throw it again.

Embedding AzLang

The interpreter is a library as well as a CLI. The same azlang.js file exposes a small API in Node and in the browser.

In Node

const az = require('./azlang.js');

const lines = [];
const result = az.run('say "Hello from embedded AzLang!"', {
  onOutput: (line) => lines.push(line),
  ask: (question) => 'Ada',
  maxSteps: 1000000
});

console.log(lines);        // [ 'Hello from embedded AzLang!' ]
console.log(result.steps); // interpreter steps used
console.log(result.ms);    // wall-clock milliseconds

Async programs

az.run() is synchronous and remains the simplest choice for programs without network or timer work. When a program uses await, use az.runAsync(); it returns a promise that resolves to the same {output, steps, ms} shape and rejects with an AzError. 

const az = require('./azlang.js');

az.runAsync(`
  let response = await http_get("https://example.com/api")
  raise_for_status(response)
  say response_json(response).title
`, {
  maxTimeMs: 15000,
  maxRequests: 10,
  requestTimeoutMs: 5000,
  onOutput: (line) => console.log(line)
}).then((result) => {
  console.log('steps:', result.steps, 'ms:', result.ms);
}).catch((err) => {
  console.error(err.kind, err.message);
});

Calling async work through run() raises an error with a hint pointing to runAsync. This keeps the synchronous API honest instead of silently dropping unfinished work.

Sessions and the REPL

run always starts with a fresh environment. To keep variables between calls, create a Session: 

const az = require('./azlang.js');

const session = az.createSession({
  onOutput: (line) => console.log(line)
});

session.execute('let total = 0');
session.execute('total += 41');
session.execute('total += 1');
session.execute('say total');       // prints 42

session.execute(source) parses and runs one chunk in the persistent environment. It returns { steps, totalSteps }. Errors are thrown as AzError objects with message, line, kind, and hint. 

const session = az.createSession({
  onOutput: (line) => console.log(line),
  requestTimeoutMs: 5000
});

await session.executeAsync('let res = await http_get("https://example.com")');
await session.executeAsync('say res.status');

session.executeAsync(source) is the asynchronous counterpart. It returns the same step counts and preserves variables between calls, so a REPL can mix sync and async lines. The CLI REPL uses this path.

Not a security sandbox

The interpreter limits steps, time, and network resources, but those limits are reliability features, not a security boundary. AzLang programs can make arbitrary HTTP requests, and modules can be loaded from local files or URLs. A browser applies its own CORS and same-origin rules, while Node.js does not. Only run programs and import modules you trust.

Style guide

AzLang does not force a style, but consistent code is easier to read, review, and teach. These conventions match every example and the Studio's starter program.

Formatting

  • Use two spaces per indentation level. Never mix tabs and spaces.
  • Put one statement per line. Semicolons are available for compact snippets, not for dense code.
  • Keep lines under about 90 characters; break long expressions with parentheses.
  • Leave one blank line between functions and classes, and around logical groups of statements.
  • Always close a block on its own line.

Names

let user_name = "Ada"          # variables: snake_case
let is_ready = true            # booleans read as questions or states
const MAX_RETRIES = 3          # constants: UPPER_SNAKE_CASE

fun calculate_total(items)     # functions: a verb or a clear noun phrase
  return sum(map(items, item => item.price))
end

class BankAccount              # classes: PascalCase
end

Choose clarity over cleverness

AzLang supports compact expressions such as reduce(nums, (a, b) => a + b), but a named function is often kinder to the next reader: 

let prices = [3, 5, 2]

# Fine for a small, local use
let total = reduce(prices, (a, b) => a + b, 0)

# Clearer when the rule matters or is reused
fun add_prices(total, price)
  return total + price
end

let grand_total = reduce(prices, add_prices, 0)

Prefer small functions

  • A function should do one thing and have a name that says what it does.
  • Return early instead of nesting deeply.
  • Keep side effects (printing, mutation) visible and intentional.
  • Use parameters instead of reaching for outer variables when possible.

Useful defaults

  • Use const for values that should never be reassigned; use let otherwise.
  • Give functions default parameters when a sensible default exists.
  • Use maps for structured records and for named options.
  • Use raw strings for JSON and paths.
  • Throw maps with a message and a code; catch close to the failure.
  • Comment why, not what. The code already says what.

Avoid

  • Shadowing built-ins like len, map, or type.
  • Very long blocks; extract a function instead.
  • Magic numbers scattered through the code; name them as constants.
  • Deeply nested if chains; use elif, early returns, or match.
  • Catching an error and doing nothing. At minimum, log the message.

FAQ

Is AzLang just Python with different keywords?

It is inspired by Python's readability, but it is an independent language with its own parser and runtime. There are no Python objects, no list comprehensions, and blocks use end instead of indentation. AzLang has its own small module system, but no package registry.

Can I use Python or npm libraries?

No. AzLang is self-contained and has no third-party package ecosystem. Its standard library is the set of built-in functions documented above plus the built-in net module. You can split your own code into .az modules and import them by path.

Does it support Persian?

Yes. Strings can contain Persian text, identifiers may use Persian letters, and number literals may use Persian or Arabic-Indic digits. Keywords and error messages remain English so the whole language surface stays consistent.

Is indentation significant?

No. Indentation is for humans only. Blocks are defined by keywords and end. The Studio auto-indents to help you.

Why end everywhere?

An explicit closer is unambiguous, works in any editor, and makes nesting obvious even when code is copied into a chat or a slide. It also means the language never reports confusing indentation errors.

Is there a ternary operator?

No. Use an if/else block or a small function. See Conditions.

Do I need to install Node.js?

No on Windows. The installer includes its own Node.js runtime and starts the browser Studio through a small local server. Install Node.js 18 or newer only when you run node azlang.js or node studio-server.js from a source checkout on another platform.

Can I split code across files?

Yes. Use import and export to create modules. Paths resolve relative to the importing file, and a module may itself import other modules. See Modules.

Can I call web APIs?

Yes. http_get, http_post, and the other network helpers work in Node and in the browser. Use await, check the status with raise_for_status, and read optional fields with get_path. See Networking & APIs.

Can I read or write files from an AzLang program?

There is no general file API. The CLI reads the source file and imported modules; input() reads standard input; say writes output. HTTP is available. A host application can expose file access through a custom moduleLoader or by extending the runtime.

Does it have static methods or private fields?

No. Classes have instance fields and methods only. All fields are public.

Can I use it for production software?

It is an educational and scripting language, designed for clarity rather than maximum throughput. It is fine for lessons, demos, small tools, and prototypes. For large production systems, use a language with a mature ecosystem.

How fast is it?

It is a tree-walking interpreter, so it is much slower than compiled languages but plenty fast for learning programs and small scripts. The step limit protects the browser from infinite loops.

Can I extend the language?

You can define any functions and classes you like in AzLang itself. The runtime is a single readable JavaScript file, so you can also add built-ins or syntax by editing azlang.js. Run node tests.js afterward.

Is it free?

Yes. AzLang is released under the MIT license. You can use, modify, and share it, including in commercial projects, with attribution.
